# Attribution — non-negotiable

Credit is given where it is due. Always. This is a core value of this
repository, not a courtesy: the toolkit exists because a community of
practitioners, authors, and tool builders shared their work, and every part
of this repo that stands on that work says so.

## The rules

1. **Every adopted idea carries its credit.** A technique, pattern, or
   approach learned from someone lands in the repo with (a) a named credit
   in the file that implements or teaches it, and (b) an entry in
   [CREDITS.md](../../CREDITS.md). No exceptions — "it's common knowledge
   by now" is not a reason to drop a name we learned it from.
2. **Credit ≠ copy.** We cite and link; we never copy text, specs, code, or
   assets. Everything is re-derived in this repo's own words. Attribution
   makes that honest, not optional.
3. **Tools are credited and licensed.** Every external tool names its
   authors and license (DEPENDENCIES.md); license terms are respected even
   when inconvenient (the pbir CLI's non-commercial terms are the standing
   example).
4. **Credits survive edits.** Rewriting a file does not strip its credit
   line. Removing or weakening an attribution is a **blocker-severity
   defect**, treated like a failing validator: fix the cause, never work
   around it.
5. **New sources join the register.** When work draws on someone new, add
   them to `contracts/source-register.yaml` (right tier) *and* CREDITS.md
   in the same change — a `/scout` run that adopts an idea does this as
   part of implementation, not as cleanup later.
6. **Forks inherit the duty.** Anyone sharing or forking this repo carries
   the credits with it; CREDITS.md states this.

When in doubt, credit. Over-attribution costs a line; under-attribution
costs integrity.
